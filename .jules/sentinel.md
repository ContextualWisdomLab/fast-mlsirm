## 2025-02-14 - Fix JSON-based DoS in HTML Report Generation
**Vulnerability:** The HTML diagnostics report generator (`render_diagnostics_report`) in `python/fast_mlsirm/report.py` directly read and parsed potentially large file inputs into memory using `source.read_text()` and `json.loads()`.
**Learning:** This approach lacked bounds checking, creating a risk for memory exhaustion or unbounded recursion DoS if an attacker provided a massive or deeply nested JSON file as input to the diagnostics CLI tool. It bypassed the existing security constraints defined in the project's internal I/O utilities.
**Prevention:** Always use the project-specific bounded deserializers (like `_load_json_bounded` in `fast_mlsirm.io`) which strictly enforce maximum input bytes and JSON nesting depths instead of standard library calls on user-provided file paths.
