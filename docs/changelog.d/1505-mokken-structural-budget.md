# Bound Mokken structural traversal

## Fixed

- Bound exact built-in Mokken response traversal to 40,000,000 structural nodes before NumPy materialization or compiled-core discovery, independently of the existing 20,000,000 logical-cell envelope. Every valid non-empty persons × items matrix inside the logical-cell domain remains admitted because row containers plus scalar cells are at most `2N` for `N` response cells. Loevinger scalability, Mokken Z statistics, and AISP numerical arithmetic remain Rust-owned and unchanged.
- For exact rectangular built-in response matrices, derive the common item width from callback-free row metadata and enforce the existing 4,000,000-cell quadratic item-pair budget before scalar score traversal or NumPy materialization. Logical-cell and structural-node limits retain precedence, and ragged, flat, higher-rank, and unsupported carriers keep their established diagnostics.
- Validate the compiled Rust Mokken result envelope before public NumPy marshalling: require the current exact built-in dict/list/float/int carriers and replay `n_items²`/`n_items` vector cardinalities before reshape or conversion. Seal each admitted exact coefficient/statistic list and the exact AISP scale list into bounded package-owned snapshots, then replay each snapshot's cardinality before scalar identity/domain validation and NumPy conversion, so provider mutation between the source-length observation and the copy, or at either later conversion seam, cannot redefine already-admitted evidence. Seal the coefficient result as the exact six-key current PyO3 contract before any required-field lookup, rejecting extra fields and non-exact-string keys without executing provider-owned key-comparison callbacks. Replay the live Rust coefficient/statistic structure as well: `hij` and `zij` must be exactly symmetric with NaN only on their diagonal, while `hi`, `h`, `zi`, and `z` must be finite. Stale/foreign native payloads with finite pairwise diagonals, non-finite off-diagonals or aggregate statistics, asymmetric mirrored pairs, or post-admission vector resizing now fail closed before publication; Python validates deterministic result structure only and does not recompute H/Z arithmetic. Validate the coefficient/statistic envelope immediately after `mokken_coef_h` and before invoking AISP, so an already-invalid native result cannot trigger avoidable second-stage Rust work or mask the package-owned result diagnostic. After that validation has produced package-owned arrays, release the temporary native coefficient dict/list envelope before AISP begins so maximum-width analyses do not retain both original quadratic Python lists and their admitted float64 copies through second-stage native work. Replay every exact AISP scale label against the concrete PyO3 `Vec<u32>` scalar domain, the live Rust formation-order ceiling `floor(n_items / 2)`, and the deterministic formation structure: positive labels are contiguous from 1 with no gaps and every formed scale label occurs at least twice because a scale is created only after selecting a fresh start pair. Negative, wider-than-u32, skipped, singleton, resized, or otherwise impossible stale/foreign native scale evidence now fails with the package-owned result diagnostic before NumPy marshalling; Python does not rerun AISP selection arithmetic.
- Preserve Mokken semantic-control values across the Python-to-Rust `f64` boundary: on platforms where `np.longdouble` is wider than binary64, exact NumPy scalar and exact 0-D-array `lower_bound`/`alpha` values that cannot round-trip through float64 now fail closed before response traversal or compiled-core discovery instead of being silently rounded. Exactly representable trusted controls and the existing finite/range semantics remain unchanged; lower-bound and significance arithmetic stay Rust-owned.
- Normalize exact built-in integer Mokken semantic controls that overflow Python's binary64 conversion into the package-owned finite-control `ValueError` before response traversal or compiled-core discovery, instead of leaking incidental `OverflowError`. Ordinary finite controls retain their existing interval semantics and all lower-bound/significance arithmetic remains Rust-owned.
- Seal exact top-level NumPy response matrices into a dtype-preserving package-owned snapshot before response-value validation or Rust dispatch. Before allocating that snapshot, reject invalid rank, quadratic item width, complex/unsupported storage, and storage whose inert byte footprint exceeds the package's admitted real-numeric allocation envelope; then replay the logical-cell ceiling and the same shape/storage contracts on the copied snapshot before finiteness, signed-int64, category, and contiguous-marshalling validation. This prevents unsupported fixed-width/structured arrays from consuming their byte footprint merely to reach a later dtype rejection, preserves the existing diagnostics, and ensures an already-contiguous caller-owned `int64` array cannot alias the Rust-bound score vector or be rewritten after admission.
- Seal exact built-in list/tuple response evidence into a bounded package-owned whole-sequence snapshot after callback-free structural/resource preflight and before dense NumPy materialization. Mutable list rows and nested exact NumPy rows are copied before `np.asarray`, then the snapshot replays logical-cell, structural-node, rectangularity, item-pair, storage, and scalar-identity constraints; the dense result also replays the 20,000,000-cell ceiling for every carrier. Caller mutation at the materialization seam therefore cannot redefine Rust-bound scores, and row growth after preflight cannot bypass the package resource envelope. This changes validation/provenance only; Loevinger H/Hij/Hi, Mokken Z, covariance/max-covariance, and AISP arithmetic remain Rust-owned.
- Reject inert unsupported or over-budget storage metadata on exact nested NumPy rows during the bounded first traversal, after the existing logical/structural/shape/item-width precedence but before duplicating a built-in outer list. Post-copy storage replay remains in place so caller mutation at the row-copy seam still fails closed; the repair removes an avoidable `O(n_persons)` pointer snapshot from requests whose nested row storage is already known to be inadmissible without changing Mokken numerical semantics.
- Reject direct-Rust Mokken `i64` score evidence that cannot be represented exactly by the binary64 covariance kernel before any `i64 -> f64` projection. Both `coef_h` and `aisp` now share this canonical admission check; exactly representable large integers remain admissible, while values such as `2^53 + 1` fail instead of being silently rounded to a different observed score. Python's tighter practical score/category admission remains an earlier binding boundary rather than the owner of this Rust numerical invariant.
- Preserve AISP's significance gate for every admitted positive binary64 `alpha`, including extreme upper tails. The standard-normal upper-quantile helper now evaluates tail branches from `p` directly (and uses `ln_1p(-p)` in the opposite tail) instead of first rounding through `1.0 - p`; tiny Bonferroni-adjusted probabilities therefore remain finite critical values rather than becoming `NaN` and accidentally admitting insignificant item pairs.
