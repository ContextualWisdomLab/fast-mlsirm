# Bound Mokken structural traversal

## Fixed

- Bound exact built-in Mokken response traversal to 40,000,000 structural nodes before NumPy materialization or compiled-core discovery, independently of the existing 20,000,000 logical-cell envelope. Every valid non-empty persons × items matrix inside the logical-cell domain remains admitted because row containers plus scalar cells are at most `2N` for `N` response cells. Loevinger scalability, Mokken Z statistics, and AISP numerical arithmetic remain Rust-owned and unchanged.
- For exact rectangular built-in response matrices, derive the common item width from callback-free row metadata and enforce the existing 4,000,000-cell quadratic item-pair budget before scalar score traversal or NumPy materialization. Logical-cell and structural-node limits retain precedence, and ragged, flat, higher-rank, and unsupported carriers keep their established diagnostics.
- Validate the compiled Rust Mokken result envelope before public NumPy marshalling: require the current exact built-in dict/list/float/int carriers and replay `n_items²`/`n_items` vector cardinalities before reshape or conversion. Seal each admitted exact coefficient/statistic list into a bounded package-owned snapshot before scalar identity/domain replay and NumPy conversion, so provider mutation at the conversion seam cannot redefine already-admitted evidence. Seal the coefficient result as the exact six-key current PyO3 contract before any required-field lookup, rejecting extra fields and non-exact-string keys without executing provider-owned key-comparison callbacks. Replay the live Rust coefficient/statistic structure as well: `hij` and `zij` must be exactly symmetric with NaN only on their diagonal, while `hi`, `h`, `zi`, and `z` must be finite. Stale/foreign native payloads with finite pairwise diagonals, non-finite off-diagonals or aggregate statistics, or asymmetric mirrored pairs now fail closed before AISP; Python validates deterministic result structure only and does not recompute H/Z arithmetic. Validate the coefficient/statistic envelope immediately after `mokken_coef_h` and before invoking AISP, so an already-invalid native result cannot trigger avoidable second-stage Rust work or mask the package-owned result diagnostic. After that validation has produced package-owned arrays, release the temporary native coefficient dict/list envelope before AISP begins so maximum-width analyses do not retain both original quadratic Python lists and their admitted float64 copies through second-stage native work. Replay every exact AISP scale label against the concrete PyO3 `Vec<u32>` scalar domain, the live Rust formation-order ceiling `floor(n_items / 2)`, and the deterministic formation structure: positive labels are contiguous from 1 with no gaps and every formed scale label occurs at least twice because a scale is created only after selecting a fresh start pair. Negative, wider-than-u32, skipped, singleton, or otherwise impossible stale/foreign native scale evidence now fails with the package-owned result diagnostic before NumPy marshalling; Python does not rerun AISP selection arithmetic.
