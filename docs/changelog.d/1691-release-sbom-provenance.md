# Release SBOM and builder-local provenance

## Fixed

- Release evidence now requires builder-local provenance for the sdist and every wheel plus a separately published SPDX JSON source-release SBOM generated from the exact reviewed release commit. GitHub release and PyPI publication are both gated on successful SBOM generation, validation, and attestation, while the PyPI upload set remains restricted to package distributions. The repository-owned SBOM gate parses the generated document fail closed, rejects non-standard numeric constants and duplicate JSON object members, and replays the mandatory SPDX 2.3 document-creation envelope (`SPDX-2.3`, `CC0-1.0`, `SPDXRef-DOCUMENT`, non-blank single-line document name, absolute fragment-free namespace URI with RFC 3986-valid percent escapes, exact second-resolution UTC `YYYY-MM-DDThh:mm:ssZ` creation timestamp, and at least one non-blank single-line creator identity) before attestation/publication. The evidence scope and primary-source basis are documented explicitly; the standalone source-tree SBOM is not misrepresented as a per-wheel SBOM predicate or as proof of a SLSA Build Level. The newly introduced SBOM job also uses the repository's explicit Ubuntu 24.04 Linux runner contract rather than reintroducing the moving `ubuntu-latest` alias owned by the separate runner-pinning lane.
