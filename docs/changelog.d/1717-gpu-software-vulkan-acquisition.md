# GPU evidence acquisition boundary

Required GPU parity had a reproducible pre-execution failure on `#1710@3d86242e60210a2cc44196fbaa3dcf2a558033f1`: CI run `34587332914` failed twice while acquiring Mesa/Vulkan packages, with attempt-2 job `103226335981` reaching the workflow's 120-second `apt-get update` bound before any adapter, package, or GPU parity code ran. CPU Python, Rust, fuzz, and package jobs on the same exact head succeeded. This is infrastructure acquisition failure, not psychometric or GPU numerical evidence.

RED `d9c2cf40726d046d05c644e6947088f3c6be4214` adds a repository contract that forbids live apt acquisition in required GPU evidence and requires one reusable software-Vulkan setup path for both PR parity and scheduled literature recovery.

The first repair `24d0132f14c05462b2bc2f12e2688f7f73c96b1f` consumed the software Vulkan payload already present in the pinned GitHub Ubuntu 24.04 image through Google Chrome: `vk_swiftshader_icd.json`, `libvk_swiftshader.so`, and `libvulkan.so.1`. Hosted CI `34592814994` proved that image contract, loader setup, dependency installation, and the targeted pytest command all reached execution without the former network acquisition failure. Its post-test no-skip gate still failed, exposing that wgpu did not admit the image SwiftShader adapter under its default underlying Vulkan-compliance policy.

Follow-up RED `06bd247329fd43ff98208c272117e3595ef1cdee` requires the non-compliant software-driver decision to be explicit at the fast-mlsirm boundary. The causal repair keeps wgpu's compliant-adapter default for ordinary production callers and enables `wgpu::InstanceFlags::ALLOW_UNDERLYING_NONCOMPLIANT_ADAPTER` only when `FAST_MLSIRM_ALLOW_NONCOMPLIANT_SOFTWARE_VULKAN=1`. The repository-owned setup helper sets that opt-in only for the controlled software-GPU evidence jobs. This follows wgpu 30's documented contract: the flag exists primarily for testing Vulkan drivers whose underlying compliance version would otherwise cause wgpu to hide the adapter.

The helper continues to validate that the manifest resolves exactly to the expected image-bundled driver, fails closed if any image-owned file is absent, records SHA-256 identity in the job log, exports the current `VK_DRIVER_FILES` loader override rather than deprecated `VK_ICD_FILENAMES`, and configures job-local runtime/library paths. No package mirror, elevated install, skipped parity, relaxed timeout, numerical fallback, or default production opt-in is introduced.

Acceptance requires the ordinary PR GPU job to execute `tests/test_marginal_parity.py::test_marginal_gpu_agrees_with_cpu_loosely` with zero skips and the scheduled paper-design recovery job to use the same setup while executing the ignored Rust GPU recovery test normally. If the hosted image removes or redirects the Chrome SwiftShader payload, or if wgpu still cannot create a usable adapter after the explicit test-only compliance opt-in, the evidence lane remains RED rather than claiming GPU parity.
