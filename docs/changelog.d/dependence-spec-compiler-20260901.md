# Dependence specification compiler

## Added

- Added a typed, non-numerical Model Specification bounded context that composes response-kernel, dimensional, generalized-mixed, identification, recovery, and dependence metadata and automatically materializes LSIRM, MLSIRM, and DLSJM candidates as `supported`, `research_candidate`, or `unsupported` without silently falling back to the base model. DLSJM keeps distinct item- and person-dependence spaces, and temporal evolution remains TEPP-owned.
- Replaced free-form generalized-mixed membership labels with explicit classification, multiplicity, weight-authority, and classification-axis contracts. Cross-classification remains distinct from multiple membership; every declared cross-classification axis has a unique identity; model-estimated membership weights require their own named recovery metric before support promotion.
- Versioned the compiled candidate manifest as `fast_mlsirm.model_specification.candidate_manifest@1.0.0` and added a deterministic SHA-256 self-digest over the canonical manifest payload for downstream ACL/provenance checks.
- Bound the support-promotion citation gate to the compiled dependence family: nonblank but unrelated references no longer satisfy `primary_citation_required`; the candidate evidence must include the canonical primary citation declared by its LSIRM, MLSIRM, or DLSJM dependence contract.
- Sealed `evidence_by_candidate_id` at the compiler boundary as an exact built-in dictionary of exact candidate IDs to `CapabilityEvidence`. The compiler snapshots that carrier before constructing any candidate identity, so mapping callbacks cannot mutate structural state between identity derivation and manifest assembly.
- Kept estimator, identification, and recovery evidence candidate-scope coherent across dependence expansion: a record scoped to one exact candidate is preserved only for that candidate, while sibling LSIRM/MLSIRM/DLSJM manifests receive explicit incomplete records scoped to their own canonical IDs instead of digesting another candidate's support evidence.
- Added immutable `CandidateSupportRecords` keyed by exact compiled candidate ID so one compilation can publish independently implemented, identified, and recovered LSIRM/MLSIRM/DLSJM candidates without borrowing sibling evidence. Existing singleton support fields remain a one-candidate compatibility path, and conflicting same-candidate legacy/catalog records fail closed.
- Replaced `MappingProxyType` as the support-catalog admission marker with a package-owned immutable mapping. Caller inputs must be exact built-in dictionaries, so a proxy around a callback-capable mapping is rejected before iteration; `dataclasses.replace()` can safely re-admit only the already sealed package representation without executing caller mapping protocols.
- Reconciled admitted documentary-evidence keys against the canonical candidates produced by the same compilation. A stale or otherwise unclaimed full candidate identity now fails closed with `unknown candidate identities` instead of disappearing from provenance while valid candidate-scoped evidence remains unchanged.
