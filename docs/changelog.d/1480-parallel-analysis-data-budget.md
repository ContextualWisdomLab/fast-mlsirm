# Parallel-analysis observed data budget

## Fixed

- Bound exact NumPy and built-in persons × items evidence to 20,000,000 logical cells before contiguous `float64` marshalling, while preserving the existing 128 MiB random-eigenvalue workspace ceiling and Rust-owned Horn/Glorfeld factor-retention arithmetic.
- Mirror the same 20,000,000-cell observed-data ceiling in `mlsirm-core` immediately after checked shape arithmetic, before data-length/value validation or package-owned random-data allocation, so direct Rust callers cannot bypass the public resource envelope.
- Bound exact built-in matrix traversal to 40,000,000 structural nodes independently of logical scalar cells, preventing zero-cell empty-row fan-out from consuming unbounded Python preflight work before NumPy materialization or native-core discovery while preserving every valid non-empty matrix inside the 20,000,000-cell envelope.
- Replay exact built-in and exact NumPy row widths during bounded preflight so ragged observed evidence fails with the stable 2-D persons × items contract before NumPy materialization or native-core discovery.
- Reject flat exact built-in scalar sequences as known non-2-D evidence during bounded preflight, before NumPy shape inference, dense `float64` marshalling, or compiled-core discovery.
- Replay the complete-data finiteness contract for exact NumPy floating evidence and trusted built-in/NumPy scalar leaves during the same bounded preflight, so `NaN`/`Inf` are rejected before dense `float64` marshalling or compiled-core discovery while retaining the direct-Rust finite-data guard.
- Replay the Rust minimum design of at least three persons and two items from exact NumPy shape or bounded built-in row-width metadata before value-wise admission and dense marshalling, while retaining logical/structural resource-error precedence and the core's distinct `n_persons`/`n_items` diagnostics.
- Validate the explicit or Horn-default random-eigenvalue workspace from callback-safe item-count metadata before value-wise observed-evidence admission and contiguous `float64` marshalling, so an observed matrix inside the logical-cell envelope cannot trigger dense allocation when its benchmark workspace is already outside the 128 MiB bound.
- Research basis and scope: Horn, J. L. (1965). A rationale and test for the number of factors in factor analysis. *Psychometrika, 30*(2), 179–185. https://doi.org/10.1007/BF02289447 introduced parallel analysis by comparing observed latent roots with roots attributable to sampling error from random data. Glorfeld, L. W. (1995). An improvement on Horn's parallel analysis methodology for selecting the correct number of factors to retain. *Educational and Psychological Measurement, 55*(3), 377–393. https://doi.org/10.1177/0013164495055003002 extended the benchmark to upper-percentile random-eigenvalue criteria. The limits and admission ordering above are implementation-safety/resource envelopes around accepted complete-data input and workspace size only; they do not alter Horn's mean-random-eigenvalue criterion, Glorfeld's upper-centile criterion, correlation/eigenvalue computation, random stream, bias adjustment, or retained-factor arithmetic.
