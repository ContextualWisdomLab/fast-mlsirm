# Count-only compute usage export

## Added

- Add `CanonicalComputeUsageSink`, a provider-neutral simulation/fit metering adapter that exports only bounded compute counts and provenance references through an injected usage-event producer and canonical `usage-event/v1` validator; billing schema, pricing, rating, tax, credit, invoice, persistence, and hosted-product concerns remain downstream-owned.

## Fixed

- Seal metering input, producer-result, validator-result, and validator-to-enqueue trust boundaries with exact built-in carrier/scalar admission. Independent bounded exact-JSON snapshots now prevent successful validator callbacks from rewriting top-level or nested event evidence before durable enqueue; snapshot traversal is limited to 4,096 nodes and depth 16, and callback-bearing nested carriers fail closed before validator or enqueue observation.
- Freeze each admitted exact built-in `dict` and `list` into a package-owned shallow container snapshot before recursive exact-JSON descent, so producer-side mutation during traversal cannot splice later members from a newer mutable-container state into one durable event snapshot. List snapshots are sliced to at most the remaining node budget plus one sentinel member, while dict and persistent-identity snapshots consume bounded `islice` item snapshots, so stale cardinality preflights cannot authorize an unbounded full-container copy if a retained producer container grows before the snapshot operation.
- Admit the producer root through the same bounded exact-dict item snapshot before root-key scanning or version lookup. If a retained producer root grows after its inert cardinality preflight, at most the 4,096-node envelope plus sentinel evidence is inspected before the package resource diagnostic wins; exact-string key and exact built-in `event_contract_version=1` diagnostics are then evaluated only from the bounded package-owned root snapshot.
- Reject a package-owned exact integer `event_contract_version` other than `1` immediately after bounded root capture, before recursively snapshotting descendant JSON values. The stable version diagnostic therefore outranks unrelated descendant carrier/finite-value failures once root identity is already known invalid, avoiding unnecessary bounded traversal without weakening exact-JSON validation for admitted v1 events.
- Validate the explicit `event_contract_version=1` marker from the first package-owned exact-JSON snapshot rather than from the live producer-owned dict, so producer-side mutation at the snapshot boundary cannot make durable evidence diverge from the package's explicit v1 admission decision.
- Reject `NaN` and positive/negative infinity during package-owned exact-JSON snapshot admission before canonical validation or durable enqueue. Finite exact built-in floats remain admissible generic JSON numbers; downstream usage-event schema semantics stay validator-owned.
- Preflight impossible exact-dict cardinalities with inert `len(...)` before producer-result key scans or nested exact-JSON key inspection, so dictionaries that cannot fit within the 4,096-node snapshot envelope fail closed without unbounded key traversal.
- Reject persistent identity dictionaries larger than the five-field canonical identity allowlist before copying or scanning them; ordinary exact-string identity admission and `None` omission semantics are unchanged.
- Bound package-owned rendering of each rejected noncanonical persistent-identity field name to 128 characters before sorting and joining the diagnostic. Short field names remain verbatim and the canonical five-field allowlist/accepted-value semantics are unchanged; the cap prevents a single inert but arbitrarily long exact-string key from amplifying rejection into another unbounded package-owned allocation.
- Snapshot simulation response shape and fit model/backend metadata exactly once before producer observation. Simulation shapes must be exact two-element tuples of exact non-negative integers, preventing mixed row/item counts from mutable shape carriers; admitted fit model/backend strings are normalized from the same values that passed type validation.
- Replay the package-owned 20,000,000 response-cell envelope for both simulation shape metadata and explicit fit row/item counts before producer observation. The exact boundary and existing zero-size metering metadata remain admissible, while overflow fails from integer division without constructing a potentially huge product.
- After response-cell resource replay, require each admitted response dimension to fit the released canonical `usage-event/v1` 39-digit measurement-quantity width before producer observation. This preserves the established nonzero overflow diagnostic and zero-size metadata semantics while preventing a zero opposite dimension from allowing an unrepresentable row/item count to reach producer formatting.
- Bound optional `artifact_bytes` to the released canonical `usage-event/v1` measurement quantity width before producer observation. Exact non-negative integers through the 39-digit decimal boundary remain admissible, while larger values fail from integer comparison before producer formatting, canonical validation, or enqueue; downstream billing schema ownership is unchanged.
- Reject unsupported fit model/backend identities against the package-owned model and kernel-backend vocabularies before invoking the metering producer. Exact built-in strings are admitted before normalization, overlong impossible codes fail before case-normalization allocation, and valid model/backend codes retain their normalized producer identities.
- Bound canonical-validator result admission to 256 diagnostics. Oversized exact tuples now fail from inert cardinality before per-entry type scans or diagnostic formatting, while ordinary bounded tuple-of-string errors retain the existing first-three diagnostic report and the downstream canonical validator remains the sole schema authority.
- Bound package-owned rendering of each of the first three admitted validator diagnostics to 1,024 characters before joining the validation error detail. Short diagnostics remain verbatim and canonical validation success/failure semantics are unchanged; the cap prevents fast-mlsirm from duplicating arbitrarily large callback-owned diagnostic strings into another unbounded combined allocation.
