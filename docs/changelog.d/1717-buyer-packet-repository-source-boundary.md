# Buyer-packet repository source identity

`build_buyer_packet` now rejects source-bound procurement packets when any repository-owned product document or product manifest differs from the advertised Git `HEAD`. This closes the gap where a clean `source_commit` value could be paired with modified, staged, untracked, or ignored working-tree evidence and then archived as if those bytes came from that revision.

The focused regression first demonstrated the defect by committing the product evidence, modifying `README.md` without committing it, and expecting packet admission to fail. The causal repair validates the fixed repository evidence paths with Git porcelain status, including ignored/untracked entries, before the canonical collector reads them. This validation is confined to the buyer-evidence boundary; LSIRM/MLSIRM/IRT likelihood, estimation, scoring, recovery, simulation, GPU arithmetic, and public numerical semantics are unchanged.

Existing packet fixtures now commit repository-owned evidence and carry the source identities already required by sales-readiness and optional benchmark/release manifests, so the tests exercise the intended source-bound contract rather than an obsolete unbound fixture.

The source-boundary is also enforced after archive materialization. RED `88e5f07f478ea01f9386ae1a411dc0621ebe8d1d` mutates committed `README.md` after the source-entry size/SHA-256 seal but immediately before either the payload ZIP or the final delivery ZIP reads that path. The predecessor implementation could therefore return a successful packet whose archived bytes differed from the per-entry digests it advertised. Causal repair `751498bbcb831953af055e0962ce25c2371fd115` reopens both generated archives, requires an exact non-duplicated member set, and streams every member through SHA-256 while checking the sealed uncompressed size. Any mismatch fails closed and removes the generated payload, delivery packet, detached packet digest, report, and manifest instead of leaving a consumable success artifact. This is a buyer/procurement provenance repair only; the psychometric numerical engine and public numerical semantics remain unchanged.

Source identity now also survives a clean repository ref transition during packet construction. Source-level RED `acf6387681a73233aff236cb3dcf8e1c90a82976` advances Git `HEAD` to a new ordinary commit after the packet has captured its advertised source revision but before canonical collection completes. A clean working tree alone cannot detect that transition, so the predecessor could finish a packet carrying the earlier `source_commit` after repository authority had moved. Causal repair `b0218c790765dd10e6e47a344639a8dc33555a3e`, kept formatter-clean by `653fb5def6f755b52aa66834e5941ef28062e115`, replays Git `HEAD` after both archives have passed member/digest verification and requires exact equality with the source revision captured at build start. A mismatch fails closed through the existing generated-output cleanup path. The check does not broaden repository cleanliness policy or alter numerical, statistical, or foreign-owner behavior.
