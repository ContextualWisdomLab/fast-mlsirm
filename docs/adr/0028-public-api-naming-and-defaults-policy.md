# ADR-0028: Public API naming convention and unsourced-defaults policy

Status: **Proposed**
Date: 2026-09-17
Supersedes: none
Superseded by: none

## Context

`python/fast_mlsirm` exposes 656 public Python callables (241 functions and
classes re-exported through `fast_mlsirm/__init__.py` and `_legacy_init.py`,
plus every submodule's own public names) and 222 PyO3 entry points compiled
from `crates/fast-mlsirm-py` (see `docs/api/inventory-20260917.csv`,
regenerated by `tools/inventory_public_api.py`). Maintainer review (#1959)
found the naming and default-argument conventions across that surface to be
inconsistent and, for many numeric defaults, unsourced:

- **Naming.** The same scope/model qualifier appears on both sides of the
  verb depending on the function: `polytomous_expected_response` (prefix) vs.
  `score_polytomous` / `fit_lsirm_polytomous` / `cat_simulate_polytomous`
  (suffix or buried mid-name); `focal_expected_total_score_monotonicity` vs.
  `bifactor_expected_total_score_monotonicity` disagree on which qualifier
  leads; the DIF family splits between prefix (`dif_polytomous`,
  `dif_analysis`) and suffix (`mantel_haenszel_dif`, `gmh_dif`,
  `breslow_day_dif`, `logistic_dif`) placement of `dif`; `_legacy_init.py` is
  itself an ad hoc export surface rather than a documented re-export policy.
- **Defaults.** `python/fast_mlsirm/polytomous.py::dif_polytomous_purified`
  defaulted `q_theta=21` (quadrature node count, no source, below the
  AGENTS.md/#1929 floor of 121), `model="gpcm"` (silently diverging from the
  GRM used in the repository's own study measurement models),
  `max_iter=200`, `tol=1e-05`, `fdr_q=0.05`, `max_rounds=3`, and
  `min_anchor_items=4` with no citation for any of the seven (across
  `dif_polytomous`, `dif_polytomous_purified`, and
  `dif_polytomous_anchor_sets`) — #1958, merged as #1960 during this ADR's
  drafting, made all seven required caller arguments and is now this ADR's
  first applied precedent (rule 1-4, below) rather than an open example; its
  decisions are carried in `docs/api/renames-and-defaults-20260917.csv` as
  `n/a` (no remaining default) rather than re-derived. The same unsourced
  pattern recurs everywhere else in the inventory: quadrature/node-count
  parameters ranging
  7-4000 with no documented floor rationale; `max_iter` ranging 10-10000 and
  `tol` ranging `1e-3` to `1e-10` with no stated convergence criterion;
  replicate/bootstrap counts (`n_rep=200`, `n_boot=1000`, `n_draws=5`) with no
  Monte-Carlo-error justification; decision thresholds (`alpha=0.05`,
  `se_threshold=0.3`, `flag_threshold=-1.645`, `min_expected=1.0`) with no
  cited source; and fixed numeric seeds
  (`seed=11400714819323198485`, `seed=0`) baked into stochastic routines. A
  full search of `python/fast_mlsirm/*.py` for an in-docstring citation
  attached to any of these default *values* (as opposed to the method they
  implement) returns zero matches.

This ADR is a decision record only. It does not rename any function or
change any default (#1959 Phase 1); implementation happens per module in the
sub-issues this ADR creates (see Consequences).

## Decision drivers

- Grep-ability and predictable naming let callers and reviewers find the
  right function without reading the whole module (`fit_*` finds every
  fitter, `dif_*` finds every DIF screen).
- scikit-learn's naming guide, and statsmodels' function-naming practice,
  converge on `verb_object` (free functions: `train_test_split`,
  `fetch_openml`, `add_constant`) or bare-verb estimator methods
  (`fit`/`predict`/`score` on an object, where the object already supplies
  the noun); this repository has no estimator-object layer, so its free
  functions need the explicit verb.
- R's `mirt` package uses noun-first commands (`mirt()`, `fscores()`,
  `itemfit()`, `M2()`); fast-mlsirm intentionally departs from that style
  for the reason above, while still using `mirt`/CTT/IRT terminology
  (`fscores`-equivalent naming lives under `score_*`, `M2`-equivalent under
  `m2_*`) so domain readers can map one to the other.
- AGENTS.md's existing quadrature rule (node count is precision, never
  defaulted, never capped, minimum 121 for study-representative settings,
  citing #1929) is the template this ADR generalizes to the other
  unsourced-default families.
- A rename or a removed default is a breaking change for downstream callers
  (in particular `ContextualWisdomLab/psychometrics-commons`); the policy
  must specify a deprecation path, not just a target state.

## Ownership and dependency direction

`fast-mlsirm` owns its own public Python and PyO3 export surface and this
convention governs it exclusively. It creates no dependency on
`ContextualWisdomLab/psychometrics-commons` or any other downstream
consumer; those consumers adapt to the deprecation window described below.
This ADR does not change the ADR-0001 repository boundary or the ADR-0002
Rust/Python numerical-ownership split — it only names, and sets default
policy for, the functions and classes that boundary already governs.

## Decision

### Naming convention

Every public callable name is built from ordered segments:

```
<verb>_<model_or_family_token>_<object>_<scope_qualifier>
```

1. **Verb-first.** The first segment is an action verb from the controlled
   vocabulary below (`tools/classify_renames_and_defaults.py`'s
   `VERB_VOCAB` is this table's authoritative, checked copy — the two must
   not drift):

   | Verb | Definition |
   |---|---|
   | `fit` | estimate a model's parameters from data |
   | `score` | compute a person-level (or aggregate) score from a fitted model or response pattern |
   | `predict` | compute a model-implied expected value (response, probability, category) |
   | `simulate` | generate synthetic response data from a model/process |
   | `estimate` | compute a numeric quantity via an estimation procedure short of full model fitting (e.g. a reliability or bias estimate) |
   | `validate` | check that input/output data or a specification satisfies a stated contract |
   | `check` | evaluate whether an already-computed quantity satisfies a stated property (e.g. monotonicity) |
   | `build` | assemble a composite structure, report, or specification from inputs |
   | `render` | produce a caller-facing presentation artifact from already-computed values |
   | `select` | choose one or more items/options from a candidate set |
   | `assemble` | construct a form/test from an item pool under constraints |
   | `equate` | place two forms' scores on a common scale |
   | `evaluate` | run a procedure to produce a pass/fail or judged result |
   | `calibrate` | place item/person parameters on a common metric |
   | `resolve` | turn a caller-supplied identifier/spec into a concrete internal object |
   | `load` / `save` | read/persist data or artifacts |
   | `normalize` | rescale a quantity onto a fixed reference scale |
   | `detect` | run a screen that flags an item/response for a named condition (e.g. DIF) |
   | `compute` | calculate a numeric diagnostic/statistic with no more specific verb above applying |
   | `compare` | contrast two or more fitted models/artifacts |
   | `run` | execute a full external or multi-step procedure |
   | `analyze` | perform a named multi-step analysis producing a composite report |
   | `enumerate` | exhaustively iterate a combinatorial space |
   | `generate` | produce new content (e.g. items), distinct from `simulate`'s synthetic response data |
   | `administer` | deliver one step or a full session of an assessment |
   | `align` | bring two spaces/scales/objects into correspondence |
   | `audit` | check governance/policy compliance of an artifact |
   | `classify` | assign a discrete category/decision to an input |
   | `compile` | assemble a specification from declarative inputs into a runnable form |
   | `describe` | produce a human-readable summary of a contract/object |
   | `diagnose` | run a diagnostic screen and report the result |
   | `draw` | sample values from a distribution |
   | `execute` | carry out a previously prepared plan/pipeline step |
   | `expand` | unfold a compact representation into its full form |
   | `export` | write a caller-facing artifact to an external format/location |
   | `extract` | pull a structured subset out of a larger artifact |
   | `get` | return an already-computed or stored value with no computation |
   | `govern` | apply a governance/acceptance policy and return its verdict |
   | `link` | place two instruments/forms on a common latent scale (IRT linking) |
   | `list` | return an enumerable, unordered collection of options |
   | `migrate` | transform a versioned artifact from one schema version to another |
   | `parse` | turn external/raw input into an internal structured representation |
   | `prepare` | transform raw input into the shape a downstream routine requires |
   | `project` | map values from one representation into another (e.g. a matrix) |
   | `rotate` | apply a factor-rotation criterion to a loading matrix |
   | `route` | direct a case/item through a multi-branch decision path |
   | `smooth` | apply a smoothing procedure to raw counts/frequencies |
   | `standardize` | rescale to a fixed reference distribution (mean/SD) |
   | `count` | tally a discrete quantity |

   A bare named-method exception (no verb) is allowed only for an eponymous
   statistical procedure, algorithm, or rating system whose *published name*
   — not a verb paraphrase of it — is the term the psychometric/measurement
   literature (and this repository's own accepted ADRs 0011, 0017, 0018,
   0021, 0022, 0025) already use, e.g. `bradley_terry_mm` (ADR-0017),
   `residual_interaction_map` (ADR-0021), `delta_plot` (ADR-0018),
   `cronbach_alpha`, `sibtest`, `dimtest`, `m2`, `s_x2`, `icc`,
   `elo_rating`/`glicko_rating`, `sigmoid`/`softplus`/`logit` — a verb prefix
   here would make the function harder, not easier, to find, since callers
   search by the term they already know from the source. This exception is
   not a default: `tools/classify_renames_and_defaults.py`'s `EPONYM_KEEP`
   set is the exhaustive, hand-reviewed list of every Python callable this
   applies to (193 of 648, as of the 2026-09-17 inventory); a name that is
   not verb-first and not in `EPONYM_KEEP` is a naming violation and gets a
   proposed rename in `RENAME_MAP`, not a silent `keep`. This rule governs
   free *functions*; classes keep the existing PascalCase noun convention
   (`PolytomousFit`, `ExpectedScoreMonotonicity`), which this ADR does not
   change.
2. **Model/family token is a prefix, immediately after the verb.** When a
   function is specific to a model family (`grm`, `gpcm`, `bifactor`,
   `2pl`, `cdm`/`gdina`, `mantel_haenszel`, `logistic`, `breslow_day`,
   `gmh`), that token comes directly after the verb:
   `fit_bifactor_grm`, `fit_bifactor_grm_multigroup`,
   `detect_dif_mantel_haenszel` (renaming `mantel_haenszel_dif`),
   `detect_dif_breslow_day` (renaming `breslow_day_dif`). This matches the
   majority placement already observed for `bifactor` (8 of 9 occurrences
   are prefix/mid, only `direct_enumeration_bifactor` is a trailing
   exception) and regularizes the DIF family, which currently splits
   roughly evenly between prefix and suffix placement of `dif`.
3. **Scope qualifier (data-shape qualifier) is a trailing suffix, always
   the last segment.** `polytomous`, `dichotomous`, `multigroup`, and
   comparable data-shape qualifiers go last, after any object noun:
   `score_polytomous`, `fit_lsirm_polytomous`, `fit_bifactor_grm_multigroup`,
   `compute_item_fit_polytomous`, `predict_expected_response_polytomous`
   (renaming `polytomous_expected_response`, prefix violation),
   `compute_information_criteria_polytomous` (renaming
   `polytomous_information_criteria`, prefix violation),
   `diagnose_local_dependence_polytomous` (renaming
   `local_dependence_polytomous`, which already had `polytomous` trailing
   and only needed a verb — the rename must not move it to prefix just
   because other `polytomous_*` violations were prefix). This matches the
   majority placement already observed for `polytomous` (13 of 18
   occurrences are trailing pre-rename) and for `multigroup` (2 of 2
   occurrences already trailing — no violation, kept as the pattern).
4. **A function name never carries the same qualifier in two positions**
   (e.g. no `fit_polytomous_polytomous_grm`). When both an object noun and
   a scope qualifier are present, the object goes immediately after the
   verb/model segment and the scope qualifier stays last:
   `<verb>_<model_or_family_token>_<object>_<scope_qualifier>` (rule 3
   applies to the whole name, not just to a bare `<verb>_<scope>` pair) —
   e.g. `detect_dif_anchor_sets_polytomous` (renaming
   `dif_polytomous_anchor_sets`, which had put the object `anchor_sets`
   after the scope qualifier). A pure variant/modifier suffix that is not a
   noun object of the function (`_purified`) stays after the scope
   qualifier, since it modifies the whole named procedure rather than
   naming a returned object: `detect_dif_polytomous_purified`,
   `detect_dif_logistic_purified`.
5. **`_legacy_init.py` is deprecation-only.** No new public name is added
   there; it exists solely to re-export names during the one-minor-release
   deprecation window this ADR requires (Migration, below). Once every
   aliased name's deprecation window closes, the corresponding entry is
   deleted from `_legacy_init.py` rather than left permanently.
6. **PyO3 entry points are implementation details, not the naming
   surface.** `fast_mlsirm._core` (and the secondary `_ata_core`,
   `_bifactor_core`, `_rotation_core`, `_multilevel_core`,
   `_rating_range_core` extension modules) are private-by-convention
   (leading underscore) and are exempt from the verb-first/prefix/suffix
   rules above — their names only need to stay traceable to the Python
   wrapper that calls them (`docs/api/renames-and-defaults-20260917.csv`
   records the current mapping). A PyO3 rename is only forced when the
   Python-level wrapper it backs is renamed and keeping the old Rust symbol
   name would confuse that traceability.

Citations for the general free-function verb-first pattern: scikit-learn
API design (`train_test_split`, `fetch_openml`,
<https://scikit-learn.org/stable/developers/develop.html#apis-of-scikit-learn-objects>)
and statsmodels' function naming (`add_constant`, `acf`,
<https://www.statsmodels.org/stable/api.html>); contrasted with R `mirt`'s
noun-first commands (Chalmers, 2012, *Journal of Statistical Software*,
48(6), `mirt()`/`fscores()`/`itemfit()`/`M2()`) as the convention this
repository deliberately does not follow for free functions.

### Defaults policy

A public callable's parameter may keep a non-`None`, non-placeholder
default only under one of these rules; otherwise the parameter becomes
**required** (no default) in Python and, where the corresponding PyO3
`#[pyo3(signature = (...))]` still lists a default, the Rust binding drops
that default too so the two layers cannot silently disagree:

1. **Numerical-precision controls** — quadrature/integration node counts
   (`q_theta`, `q_xi`, `q_u`, `q_gamma`, `n_quad`, `n_nodes`, `xi_points`,
   `m2_q_theta`, `m2_q_u`, `m2_q_xi`, `nevalpoints`, `node_dims`),
   iteration/convergence controls (`max_iter`, `tol`, `tolerance`,
   `max_cycles`, `max_line_search`, `m_steps`, `mh_steps`, `n_iterations`,
   `burn_in`, `target_accept`, `basin_tolerance`, `omega_tol`, `sig2_stop`,
   `hessian_step`, `eps`, `eps_distance`, `epsilon`), and
   replicate/draw/bootstrap counts (`n_rep`, `n_replicates`, `n_boot`,
   `n_draws`, `n_starts`, `n_sample_splits`, `k_folds`, `init_games`) are
   **required arguments** unless the docstring cites, with an APA 7th
   in-text citation and reference-list entry, a specific source that
   justifies the exact default value for this exact routine. A cited
   node-count default must still be `>= 121` per the AGENTS.md quadrature
   rule (#1929); a cited default below 121 does not qualify for `keep` and
   is `change`d to required regardless of the citation, since 121 is a
   floor, not a citable-away constraint.
2. **Decision thresholds, flag cutoffs, coverage levels, and stopping
   rules** — significance levels (`alpha`, `alpha_level`),
   multiple-comparison controls (`fdr_q`), flagging cutoffs
   (`se_threshold`, `flag_threshold`, `min_expected`, `min_discrimination`,
   `min_effect`, `person_flag_threshold`, `itemfit_penalty_weight`,
   `msq_band`, `isolation_z`, `sx2_min_effect`, `zero_tolerance`,
   `z_fast`), confidence/coverage levels (`ci_level`, `conf_level`,
   `centile`), and iteration/purification stopping rules (`max_rounds`,
   `min_anchor_items`, `min_flags_to_remove`, `j_min`) are **required
   arguments** unless the docstring cites an APA 7th source for the exact
   value (e.g. Benjamini & Hochberg, 1995, for a `fdr_q=0.05` default;
   Candell & Drasgow, 1988, for a purification `max_rounds` default) — a
   general "this function implements method X" citation for the *method*
   does not by itself source a specific *default value* for a tunable
   threshold inside that method. `ci_level=0.95`/`conf_level=0.95` are the
   same failure mode as `alpha=0.05`: a conventional value with no
   function-specific source, so `require`d, not `keep`-with-a-generic-CI-
   theory citation (a citation for confidence-interval theory in general
   does not source *this function's* choice of 95% over 90%/99%).
3. **Seeds are always required for stochastic routines.** No public
   callable that samples, bootstraps, or otherwise uses randomness may ship
   a numeric-literal default seed (`seed=0`, `seed=11400714819323198485`,
   `base_seed=...`, `shuffle_seed=...`, `xi_seed=...`). Reproducibility is
   the caller's obligation to state explicitly, not the library's to assume
   silently; a hidden shared default seed across unrelated call sites is
   itself a reproducibility hazard (two independent draws that look
   independent but are not, because they share a hard-coded seed).
4. **Model choice has no default unless the function is model-specific.**
   A function whose name already names its one model (`fit_grm`,
   `fit_bifactor_grm`) needs no `model=` parameter at all and this rule does
   not apply to it. A function that is generic across a model family
   (`fit_cdm(model="dina", ...)`, DIF functions taking `model=...`) must make
   `model` a required argument; a generic fitter defaulting silently to one
   member of its family, as `dif_polytomous_purified` did before #1960
   (`model="gpcm"` while the repository's own study models use GRM), is
   exactly the failure mode this rule forecloses — and exactly what #1960
   already fixed.
5. Parameters outside these four families — I/O paths, display/verbosity
   flags, backend/device selection (`backend`, `device`), boolean toggles
   with no statistical content (`adaptive`, `purify`, `exact`, `signed`,
   `shuffle_seed` is a seed and covered by rule 3, not this bucket) — are
   out of this policy's scope and keep their defaults; this ADR only
   reaches numerical-precision controls, decision thresholds, seeds, and
   model choice.

## Invariants / acceptance evidence

1. `tools/inventory_public_api.py` regenerates
   `docs/api/inventory-YYYYMMDD.csv` from static analysis (stubbed
   `fast_mlsirm._core` import plus `inspect.signature`, and regex extraction
   of `#[pymodule]`/`#[pyfunction]`/`#[pyo3(signature = ...)]` blocks in
   `crates/fast-mlsirm-py/src/*.rs`) with no Rust build required; re-running
   it against a later commit produces a file whose row set is a superset (no
   silently dropped callable) unless a callable was actually removed.
2. `docs/api/renames-and-defaults-20260917.csv` records, per callable, a
   `proposed_name` (`keep` or a replacement obeying the naming convention
   above) and, per defaulted parameter, a `default_decision` of
   `keep+source`, `require`, or `change`, each with a `rationale` column —
   this is the acceptance evidence that the policy above was applied
   mechanically and exhaustively to every row of the inventory, not
   selectively to the six examples in #1959's issue body. Concretely, of
   the 648 unique public Python callables in the 2026-09-17 inventory, 211
   are hand-reviewed name renames (`RENAME_MAP`) and 193 are hand-reviewed
   eponym exceptions (`EPONYM_KEEP`); `tools/classify_renames_and_defaults.py`
   raises every first-token-noncompliant name that is in neither set to a
   `name_decision` of `review` rather than defaulting it to `keep` (as of
   this inventory, that set is empty — every violation was reviewed), so a
   future name the classifier has not yet seen cannot silently pass as
   compliant.
3. A future PR that renames a function or removes a default must update the
   corresponding row's status in `docs/api/renames-and-defaults-20260917.csv`
   (or its successor date-stamped file) and add the matching `Deprecated`/
   `Changed` changelog fragment — this ADR does not self-enforce that via
   CI; the per-module sub-issues (Consequences, below) are where that
   enforcement is added.

## Non-goals and claims not made

- This ADR does not itself rename any function or remove any default beyond
  what #1958 (DIF defaults in `polytomous.py`) already did independently,
  merged as #1960 before this ADR merged: `dif_polytomous`,
  `dif_polytomous_purified`, and `dif_polytomous_anchor_sets`'s seven
  previously unsourced defaults (`model`, `q_theta`, `max_iter`, `tol`,
  `fdr_q`, `max_rounds`, `min_anchor_items`) are now required arguments.
  This ADR's tables absorb #1960's outcome rather than re-deriving or
  overriding it (see `docs/api/renames-and-defaults-20260917.csv`, module
  `fast_mlsirm.polytomous`: the three functions' default-bearing rows are
  `n/a`, no default remains; only their `rename` naming decision is still
  open work).
- This ADR does not claim every one of the 656 Python or 222 PyO3 entry
  points was individually re-derived from a primary source in this pass;
  most defaulted numerical-precision and decision-threshold parameters are
  marked `require` precisely because no such source currently exists in the
  codebase (see Context — zero in-docstring citations found for any default
  value). Sourcing a specific value where one is defensible (rather than
  making the argument required) is deferred to the per-module
  implementation sub-issues.
- This ADR does not change `fast_mlsirm._core`'s module-name contract
  (`pyproject.toml`'s `[tool.maturin] module-name = "fast_mlsirm._core"`) or
  ADR-0011's canonical-registry proposal; it only states that the private
  PyO3 layer is exempt from the public naming rules.

## Consequences and trade-offs

### Benefits

- One rule set resolves the concrete naming complaints in #1959 (`dif`
  prefix/suffix split, `polytomous` prefix/suffix split, `bifactor` outlier)
  using the majority pattern already present in the codebase, so most
  renames are minority-to-majority corrections rather than an invented new
  style.
- The defaults policy directly generalizes the AGENTS.md quadrature rule
  (already Accepted practice for node counts) to the other four families of
  previously unsourced defaults, so implementers have one policy to apply
  module by module instead of re-litigating each parameter.

### Costs / risks

- Every `require`d default is a breaking API change for existing callers,
  including `ContextualWisdomLab/psychometrics-commons`; the Migration
  section below is the mitigation, not an elimination, of that cost.
- Mechanically classifying ~300 distinct defaulted-parameter names by regex
  (Invariant 2) trades perfect per-function judgment for exhaustive, uniform
  coverage; a small number of edge cases may be misclassified and need a
  human override during per-module implementation — the sub-issues this ADR
  opens are where that correction happens, not this document.

## Alternatives considered

- **Keep the status quo (no convention, defaults as-is).** Rejected: this is
  the situation #1959 identifies as broken — inconsistent prefix/suffix
  placement and unsourced numeric defaults that silently diverge from the
  repository's own study settings (e.g. `model="gpcm"` default while study
  models use GRM).
- **Full MLS2PLM-style unification of every function into one mega-API.**
  Out of scope and rejected by the same reasoning as `AGENTS.md`'s
  "formula scope" rule: the naming/defaults convention does not change any
  model's parameterization, likelihood, or estimator; it only changes what
  callables are named and which of their arguments are required.
- **Rename everything to a fully new vocabulary instead of the majority
  in-repo pattern.** Rejected: it would maximize breakage for no additional
  clarity over adopting the pattern already dominant in the inventory.

## Failure/degraded/recovery behavior

Not applicable in Phase 1 — no runtime behavior changes. Per-module
implementation PRs must include a RED test that calling a `require`d
parameter's function without it raises `TypeError` (Python) or the
equivalent PyO3 `TypeError` from a now-mandatory positional/keyword
argument.

## Security/privacy implications

None. This ADR only concerns public function/class names and argument
defaults for numerical/statistical routines.

## Compatibility/migration/rollback and reversal/supersession conditions

**Migration plan** (applies to every row of
`docs/api/renames-and-defaults-20260917.csv` marked `rename` or with a
`default_decision` of `require`/`change`):

1. The new name (or the new required-argument signature) is added first;
   the old name remains importable as a thin alias in `_legacy_init.py` (or,
   for a changed default, the old default is kept behind an explicit
   opt-in — e.g. accepting the old value only when passed, never silently)
   for **one minor release**.
2. The alias emits a `DeprecationWarning` naming the replacement.
3. The changelog fragment for the introducing PR uses the `Changed` heading
   for a signature/default change and the `Deprecated` heading for an
   aliased rename, per the repository's allowed changelog fragment
   headings.
4. At the start of the next minor release after introduction, the alias and
   the deprecated default path are deleted in one cleanup PR that also
   removes the corresponding `_legacy_init.py` entry.

**Rollback:** reverting the introducing PR restores the old name/default
immediately (the alias makes the old and new names co-resident during the
window, so rollback is not a breaking operation for callers who adopted the
new name early).

**Reversal/supersession:** superseded by a later ADR if the maintainer
changes the verb vocabulary, the prefix/suffix assignment for a qualifier,
or the four default-policy families above.
